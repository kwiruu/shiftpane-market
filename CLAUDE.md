# ShiftPane web

The ShiftPane website: docs and the widget gallery. pnpm + Turborepo: `apps/web` (Next.js 16, App
Router, on Vercel), `apps/api` (Hono, on Heroku) and the `packages/` they share. `marketplace-plan.md`
is the plan; README.md says where each milestone is and how to deploy.

## Commands

- `pnpm lint` (Biome, whole repo) / `pnpm format` to fix
- `pnpm typecheck`, `pnpm test`, `pnpm build` (Turborepo)
- One Vitest file: `pnpm --filter @shiftpane/checks exec vitest run src/run.test.ts`
- Dev servers: `pnpm dev` (site on 3000, API on 8787). The site shows the seed unless
  `SHIFTPANE_API_ORIGIN` is set; with it, `next dev` offers local test accounts (any login, any
  role) next to GitHub sign-in. The API allows them only outside production with a localhost
  `SITE_ORIGIN` (`devSignIn` in `apps/api/src/config.ts`).
- After changing `packages/db/src/schema.ts`: `pnpm --filter @shiftpane/db generate`, and commit the migration.
- Deploy the API: `pnpm --filter @shiftpane/api deploy:heroku` (needs `HEROKU_API_KEY`, `HEROKU_APP`).

## Conventions

- The look is Dev Pane's (github.com/kwiruu/devpane-web-app) and must stay highly similar. Tokens and
  rules live in `apps/web/DESIGN.md`; their CSS is `apps/web/src/app/globals.css`. Use the token
  utilities (`text-body-md`, `bg-surface`, `text-secondary`, `rounded-lg`), never raw colors or sizes,
  except inside widget previews and the drawn devices, which are pictures of the phone and laptop.
- Import `cn` from `@/lib/utils`, not from `cn`: the configured one knows the DESIGN.md text sizes.
  `src/lib/cn-tables.ts` is generated by `next dev`/`next build`; commit it, don't edit it.
- New shadcn components: change their `cn` import, and replace `bg-accent`/`bg-secondary` with
  `bg-muted` (in DESIGN.md, `accent` is orange and `secondary` is gray text).
- The widget format (types, zod schemas, sources, permission wording, view bindings) is the app's
  `@shiftpane/widget-sdk`, and widgets are drawn by the app's `@shiftpane/board`. Both are copied into
  `vendor/shiftpane` by `pnpm sync:shiftpane` from a ShiftPane checkout beside this one: never edit
  them here, change them in the app and copy again (`pnpm sync:shiftpane --check` says if the copy is
  stale). `packages/format` re-exports the SDK and adds the gallery's checks and types; the site and
  API import from it, so permission wording matches the app's install prompt.
- Pages read the gallery through `apps/web/src/lib/registry/gallery.ts` (the API, or the seed) and
  export `revalidate = 60`. The landing page's pictures read the seed directly.
- The account pages (upload, dashboard, `/admin`) are static shells: their client components in
  `src/components/account` call `/api/v1` from the browser through `src/lib/api.ts`, and the server
  passes them `hasApi` (from gallery.ts) so they say so when there's no API.
- `first-party/` holds the first-party widgets as packages; `seed.ts` mirrors them and a test keeps
  the two in step. Raise a widget's version to publish a change.
- Internal packages export source (`"exports": "./src/index.ts"`) with `.ts` on relative imports, so
  the API runs under Node's type stripping; no enums or parameter properties (`erasableSyntaxOnly`).
- Every API body and upload is validated: zod for JSON bodies, `@shiftpane/checks` for packages.
- Previews render `view.json` with the app's `ViewWidget` only (`src/components/widgets/widget-view.tsx`),
  and the built-in widgets with its `WidgetCard` (`src/components/market/built-in.tsx`). Never
  render author-supplied HTML or run author code in the browser; READMEs go through react-markdown
  with `skipHtml`.
- Say when something is planned (`<Planned />` in docs). Don't present planned app features (Widget
  Studio, the AI generator, publishing from the CLI) as shipped. The SDK and the CLIs are on npm.
- `src/lib/split.ts` is a port of ShiftPane's `packages/layout`; keep it in step with the app.
- Shared dependency versions live in the `catalog:` in `pnpm-workspace.yaml`.
- Index keys are allowed in `src/components/widgets` (fixed, decorative lists); Biome flags them elsewhere.

## Gotchas

- API answers are `private, no-store` unless a route opts in; only the gallery's public reads
  (`routes/public.ts`) are cacheable. Never let a per-person answer (`/me`, uploads, the queue) be.
- Next.js 16 differs from older versions: read `apps/web/node_modules/next/dist/docs/` first
  (`apps/web/AGENTS.md`). `next build` type-checks with the project's TypeScript 7 `tsc`.
- Pages that read the query string (`/widgets/search`) do it in a client component under `<Suspense>`,
  so the page still prerenders.
- The content security policy in `next.config.ts` allows only this origin. Anything loaded from
  elsewhere (fonts, images, scripts) has to be self-hosted.
- Hero motion is CSS scroll-driven animation in `globals.css`; browsers without it show the end
  state. Test with reduced motion too.
